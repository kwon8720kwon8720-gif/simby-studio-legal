Why previously rejected (industry-common + our gap):
- UX Guidelines Point 2)b Privacy Status had an effective default / hardcoded SELF_ONLY path in the old demo UI.
- Old demo did not clearly show commercial disclosure, interaction toggles off-by-default, Music Usage Confirmation, express consent, or status polling.

What changed in this revision:
1. Creator info card shows nickname / username / max duration (Point 1).
2. Privacy dropdown is populated from creator_info options and has NO selected default — user must choose (Point 2b).
3. Comment / Duet / Stitch are unchecked by default; disabled/greyed when creator_info says so (Point 2c).
4. Commercial disclosure toggle OFF by default; Your Brand / Branded Content; branded content cannot be Only me (Point 3).
5. Consent text switches to include Branded Content Policy when needed + Music Usage Confirmation always (Point 4).
6. Content preview, no watermark added by app, editable title, express consent checkbox required before Post, processing notice, status polling demo (Point 5).
7. Website header always shows Terms + Privacy without opening a menu.

Scopes used:
- user.info.basic — show which TikTok account will receive the post
- video.upload / video.publish — Content Posting API after explicit user consent

Intended use:
Simby Studio helps creators publish their own short gameplay videos to their own TikTok accounts with full control of privacy, interactions, and commercial disclosure. It is not a bulk cross-post scraper of arbitrary third-party content.

Demo video:
Shows Home (Terms/Privacy visible) → Post to TikTok → creator info → select video → preview → manually select privacy → leave interactions off then optionally enable → commercial disclosure off/on → consent → Post → status updates.
